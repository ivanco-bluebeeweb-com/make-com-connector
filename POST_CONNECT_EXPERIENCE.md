# Make.com Connector — что видит и чем управляет пользователь после подключения

## 1. Целевой пользователь
No-code/ops-специалист, использующий Make (бывший Integromat) для визуальных сценариев
автоматизации между SaaS-сервисами.

## 2. Момент истины после подключения
Сразу после `connect_make` — список сценариев (`list_scenarios`) с их статусом
(активен/на паузе) и когда последний раз выполнялся — видно, что реально работает.

## 3. Что пользователь видит
- Сценарии (визуальные workflows) целиком, включая модули — `list_scenarios`,
  `get_scenario_blueprint`.
- Историю выполнений сценария с ошибками по каждому модулю — `list_scenario_logs`.
- Подключения (connections) к внешним сервисам, настроенные в Make — `list_connections`.
- Расход операций (сколько потрачено из лимита плана) — `get_organization_usage`.
- Команды и роли пользователей в организации — `list_teams`, `list_users`.
- Хранилища данных (Data Stores) — `list_data_stores`.

## 4. Чем пользователь может управлять
- Включать/выключать сценарий — `activate_scenario`, `deactivate_scenario`.
- Запускать сценарий вручную прямо сейчас — `run_scenario`.
- Клонировать сценарий как основу для нового процесса — `clone_scenario`.
- Создавать/очищать запись в Data Store — `create_data_store_record`,
  `clear_data_store`.
- Управлять расписанием запуска (по таймеру/интервалу) — `update_scenario_schedule`.

## 5. "Вау"-момент для демо потенциальному клиенту
"Смотри — говорю Webbee: 'какой сценарий упал в последний раз и на каком шаге?'. Она
находит через `list_scenario_logs` конкретный сбойный модуль — а я прошу перезапустить
руками после проверки, `run_scenario` делает это сразу."

## 6. Что делает это "заточенным под него"
`get_organization_usage` показывает РЕАЛЬНЫЙ расход операций именно этого тарифного
плана клиента — Webbee помогает не превысить лимит, а не работает вслепую.
